# Animations

A trajectory plot says where the car went. An animation says *why*, and for two
things in this repo it is the only honest way to show them: what a safety
filter takes away, and what "learning online" actually looks like when there is
no replay buffer and no batch.

All of these are generated by `rtrrl_playground.viz`, which is a normal part of
the package rather than a docs-only script — you can point it at your own agent:

```python
from rtrrl_playground import make_env
from rtrrl_playground.viz import animate_episode, animate_safety

animate_episode("overtake", my_policy, "pass.gif", follow=True)
```

To regenerate everything on this page:

```bash
python scripts/make_animations.py            # all of them
python scripts/make_animations.py --only safety
python scripts/make_animations.py --quick    # short training, smoke test
```

GIF rather than video, deliberately: matplotlib's Pillow writer needs no ffmpeg
and no ImageMagick, and a GIF renders on Read the Docs with no player.

## The safety filter, deciding

```{image} _static/anim/safety_filter.gif
:alt: a policy at full throttle held on the track by a predictive safety filter
:width: 100%
```

Left, the car. Right, the filter's verdict on all nine actions — green where a
safe backup exists, red where none does — with a **blue box on what the agent
asked for** and a **dotted box on what actually ran**. When those two separate,
the filter has intervened, and you can see what it took and why.

The policy is full throttle with random steering. That choice is not
incidental, and the two obvious alternatives are both worse:

- A **competent** policy is filtered 0% of the time. The clip would be nine
  green cells for its entire length, which is the correct behaviour of a filter
  and a useless demonstration of one.
- A **uniformly random** policy averages 0.9 m/s, which is too slow for the
  tyre limit to bind at all. Worse, behind a filter it does not crash — it
  **stalls**: 94 steps, mean speed 0.58 m/s, `stalled: True`. That is a real
  result and it is the *filter becomes the controller* failure mode described
  in [Safe learning](safety.md#failure-modes), but it animates to a stationary
  car under a caption claiming the filter is working.

Full throttle with random steering moves, gets overridden on roughly half its
steps, and is the same regime the sweeps in [Safe learning](safety.md) use.

`assumed_grip=0.6` — the worst case of the environment's $U(0.6, 1.4)$ — because
it is the only setting that never lets a crash through. At the mean, `1.0`, this
policy puts 7% of episodes into a wall.

## The same policy, behind a CBF

```{image} _static/anim/safety_cbf.gif
:alt: the same policy behind a discrete-time control barrier function
:width: 100%
```

Same car, same state, same nine actions, same seed. The only thing that differs
is the criterion: one algebraic inequality per action instead of a twenty-five
step rollout. Watching the two side by side is the clearest statement of what
[Part 2](#part-2-cbf) argues — the CBF refuses
more, because a one-step condition cannot tell that a *plan* exists, only that
the next state is acceptable.

## Learning, as it happens

```{image} _static/anim/learning.gif
:alt: the same agent at three points during online training
:width: 100%
```

The same agent at three points in training, driving simultaneously. There is no
checkpoint being reloaded between panels — training simply continues, because
there is no replay buffer to restore and no optimiser state beyond the
eligibility traces.

This is what the learning curve in [Results](benchmark_results.md) is a
projection of. The untrained policy leaves the track in a couple of seconds; the
trained one holds a line and carries speed through the corners.

## One episode, and the nine numbers it is steering on

```{image} _static/anim/lanekeep.gif
:alt: a trained agent driving lanekeep with its lidar beams drawn
:width: 100%
```

The beams are the **entire** observation — there is no pose, no map, no speed
unless `observe_speed` is on. Every beam stops where it leaves the track, which
is why the endpoints sit just past the boundary: a ray-march reports the first
sample that was off, so it overshoots by up to one `BEAM_STEP` (0.15 m).

## Overtaking

```{image} _static/anim/overtake.gif
:alt: an agent completing a pass, camera following
:width: 100%
```

Camera follows the car, because the interesting part of an overtake is about
three metres wide. **Red beams are the ones that hit a car rather than a wall** —
that flag is the only thing distinguishing an opponent from scenery, and without
it a car two metres ahead and a wall two metres ahead are the same observation,
which no amount of recurrence recovers.

The seed is chosen by searching for an episode that actually contains a pass.
That is worth stating: an earlier version of the static overtake figure showed
an episode with no pass in it, under a caption promising one.

## Writing your own

`animate_episode` and `animate_safety` both take an environment or a name, any
callable policy, and an output path. The one part worth knowing about is
`_roll`'s `intercept` hook, which sits between the policy and the environment:

```python
def intercept(env, obs, proposed):
    ...
    return action_to_apply, extra_to_record
```

Whatever it returns as `extra` is stored with the frame, which is how the
safety animation records nine verdicts per step without the rollout code
knowing what a filter is. The returned *action* is what gets applied — and that
is the part not to skip. The first version of this module recorded the filter's
decision but stepped the environment with the unfiltered action, producing a
clip of a car leaving the track under a caption saying it could not. The
function now raises rather than write that file.
